# Repository approval workflow

- Work on feature branches. Never push changes directly to `main`.
- Prepare a reviewable pull request with relevant validation results.
- Do not merge, enable auto-merge, use the owner bypass, or publish the generated website without Pritish's explicit approval for that concrete change. Earlier general instructions to continue or push do not authorize merging future changes.
- Do not approve reviews as Pritish or weaken/disable repository protections to complete a task.
- GitHub authentication currently acts as `pritchoudhary`. GitHub cannot distinguish agent actions from the owner, and a PR author cannot approve their own PR. Leave owner-authored PRs for Pritish to review and merge through the owner-only PR bypass, unless he explicitly authorizes the specific merge.
- Feature-branch pushes and opening a reviewable PR are permitted; these do not change `main` or the published website.
